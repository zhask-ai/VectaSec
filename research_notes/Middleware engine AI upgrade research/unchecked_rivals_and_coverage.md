# Unchecked rivals and coverage: is "nobody does integration-layer security posture" true as of November 2026?

Research date: 2026-11-23. Evidence labels used on every finding:

- **[P]** read on a primary page or counted from a public repository file listing in this pass
- **[V]** vendor-claimed (read on the vendor's own marketing page or press release; not independently verified)
- **[S]** seen only in a search-result summary; the underlying page was not opened

Counting method for open catalogues: GitHub tree listings fetched 2026-11-23 and matched by file or directory name. Counts are by name match, so a check whose file name does not contain the service name would be missed. "Unique" means deduplicated across IaC frameworks (Terraform, CloudFormation, ARM and so on).

## 1. Does any CNAPP look INSIDE a broker (Kafka ACLs, RabbitMQ users and permissions, Redis ACLs) rather than at cloud control-plane flags?

### Takeaway
No CNAPP or cloud-native posture catalogue that could be opened reads Kafka ACLs or RabbitMQ users and permissions; every cloud-provider and IaC check found is a control-plane flag (encryption, public access, logging, auth mode on/off). The only "inside the system" exception found in a CNAPP is Wiz's Redis host-configuration rule that parses `bind`, `requirepass` and the ACL `nopass` directive. The one product that does look inside a broker is not a CNAPP: KafkaGuard, a Kafka-only scanner with 55 controls.

### Inferences
- Across AWS Security Hub, AWS Config, Azure Policy, Defender for Cloud, Steampipe, Checkov and KICS, the deepest broker checks are "is authentication on" (MSK.6, `mq-active-broker-ldap-authentication`, `elasticache-rbac-auth-enabled`, Service Bus/Event Hub local-auth and namespace authorization rules). None enumerates principals, their grants, or wildcard resource patterns inside the data plane. The earlier pass's conclusion holds for these catalogues.
- The earlier pass's Prowler numbers are in line with first-party catalogues: Security Hub has 6 MSK, 4 MQ, 3 SQS, 3 SNS, 3 EventBridge controls.
- Azure Service Bus and GCP Pub/Sub are thinly covered in open-source IaC scanners (Checkov: Service Bus 0, Pub/Sub 2; KICS: 0 and 0) but Azure's own Policy catalogue is not thin (10 to 18 Service Bus definitions). A claim that "Azure Service Bus has zero checks" is true for Prowler/Checkov/KICS and false for Azure Policy and Steampipe (6).
- Self-managed Kafka, RabbitMQ, NATS, Kong, n8n and Confluent Cloud have zero checks in Checkov, KICS, AWS Config and Security Hub by name match. Nuclei covers them only from the outside (exposed panels, default logins, unauthenticated enumeration).
- KafkaGuard is the most direct functional overlap with VectaSec found in this pass: agentless, read-only credentials, inside-broker ACL and SASL checks, compliance mapping. It is Kafka-only.
- Wiz customers could approximate broker config checks themselves with custom host configuration rules against `server.properties` or `rabbitmq.conf` on disk. That reads static files on a VM or container, not live ACL state, and would not reach managed services (MSK, Confluent Cloud, Amazon MQ).

## 2. Does any vendor compute machine-credential last-used or ownership for broker, gateway or automation principals?

### Takeaway
No vendor was found that computes last-used or ownership for broker principals (Kafka users, RabbitMQ users, Redis ACL users) or gateway consumers. Adjacent signals exist one layer over: Microsoft flags API endpoints unused for 30 days in APIM, Logic Apps and Function Apps; SaaS-security vendors attach a human owner to automation "agents" on n8n, Make and Workato; and NHI vendors tie MCP-config secrets to an identity.

### Cited Findings
- [P] Defender for Cloud: "API endpoints that haven't received traffic for 30 days are considered unused" for Azure API Management, and equivalent recommendations exist for Logic Apps and Function Apps. This is endpoint-level usage, not credential-level. — [Microsoft Learn: API recommendations reference](https://learn.microsoft.com/en-us/azure/defender-for-cloud/recommendations-reference-api)
- [P] Defender for Cloud also flags "API Management subscriptions shouldn't be scoped to all APIs" (an over-privileged gateway credential check). — [Microsoft Learn: API recommendations reference](https://learn.microsoft.com/en-us/azure/defender-for-cloud/recommendations-reference-api)
- [V] Nudge Security (24 March 2026): "connects each agent to its human creator", lets teams "assign technical owners", and lists "agents that have outlived their creators" as a posture finding, across platforms including n8n, Make, Workato and Tines. — [Nudge Security blog](https://www.nudgesecurity.com/post/ai-agent-discovery-with-nudge-security)
- [V] Obsidian's n8n page claims a "continuous system of record for every agent" covering the MCP servers they call, the LLMs behind them, connected apps and privileges held. The page as fetched does not state owners or run frequency. — [Obsidian Security: n8n](https://obsidiansecurity.com/ai-agent/n8n)
- [S] A search summary of the same Obsidian page quoted "who owns it, what it's connected to, how often it runs, and what models power it". This wording was not confirmed in the fetched page text. — [Obsidian Security: n8n](https://obsidiansecurity.com/ai-agent/n8n)
- [V] Token Security (MCP Server Discovery, launched January 2026 per search summary): scans collected MCP config files for hardcoded secrets, ties them to an identity, and lets teams "determine who deployed each AI service". Last-used is not mentioned. Brokers, gateways and automation platforms are not mentioned. — [Token Security blog](https://www.token.security/blog/token-security-mcp-server-discovery-capability-uncovers-hidden-ai-servers-and-secrets)
- [V] Palo Alto Prisma AIRS 2.0 posture claims to find agents "including shadow or inactive agents that still hold" access. — [Palo Alto Networks blog](https://origin-researchcenter.paloaltonetworks.com/blog/2025/10/prisma-airs-powering-secure-ai-innovation.md)
- [S] An NHI Mgmt Group how-to notes each automation platform exposes its own unused-credential signal: Zapier shows Zap counts per connection, Make lists scenarios per connection, and n8n's built-in security audit flags unused credentials. — [NHI Mgmt Group](https://nhimg.org/how-to-audit-zapier-make-and-n8n-credentials)
- [S] Cloud-provider IAM has native last-used data (AWS `get-access-key-last-used`; Google Activity Analyzer for service accounts and keys). A search for the same on Kafka, Confluent, Kong or n8n principals returned nothing. — [AWS IAM docs](https://docs.aws.amazon.com/IAM/latest/UserGuide//id_credentials_finding-unused.html); [Google Cloud docs](https://docs.cloud.google.com/iam/docs/service-account-recent-usage?authuser=3)

### Inferences
- "Last-used and owner for every broker, gateway and automation credential" appears to be unclaimed for brokers and gateways. For automation platforms it is partly claimed already: Nudge states owner and orphaned-agent findings, and n8n itself reports unused credentials natively.
- IAM-authenticated cloud services (MSK with IAM auth, SQS, SNS, EventBridge, API Gateway with IAM) inherit AWS IAM last-used data, so any CNAPP or NHI tool with IAM analysis already covers those principals indirectly. The uncovered set is SASL/SCRAM users, mTLS principals, RabbitMQ users, Redis ACL users, Kong consumers and keys, SAS keys.

### Gaps
- Astrix's MCP discovery page now redirects to Cisco Identity Intelligence (Astrix was reported acquired by Cisco, completed 29 June 2026, single-source search summary). The original page could not be read; search summaries say the Astrix dashboard lists MCP servers with "usage" and "risk level". — [search summary via tech-insider](https://tech-insider.org/?p=22272)
- Oasis Security, Clutch, Entro and other NHI vendors' connector lists were not opened. Whether any has a Kafka, Confluent Cloud, RabbitMQ or Kong connector is unknown.
- Confluent Cloud, Kong Konnect and Redpanda native "last used" features for API keys were not checked.

## 3. Does any vendor assess n8n, Zapier or Make workflows themselves (triggers, credentials used, public webhooks)?

### Takeaway
Yes, in part, and this is where the "nobody" claim is weakest. At least five SaaS-security vendors now name n8n, Make, Workato or Zapier as covered platforms, mostly launched March to June 2026 and framed as "AI agent" inventory rather than workflow audit. None of the pages read states trigger-level or public-webhook-level checks, but "publicly accessible agents" and "hardcoded credentials" are stated findings.

### Cited Findings
- [V] Obsidian Security has a dedicated n8n page: finds unsanctioned agents and their connections and executions; "automatically assesses new and updated agents for risky scopes and unsafe tool chains"; alerts on "n8n configurations and connections that could expose data, enable privilege escalation, or enable confused deputy attacks"; compares connections against approved apps and MCP servers. Connection method and dates are not stated. Triggers, webhooks and stored credentials are not explicitly listed. — [Obsidian Security: n8n](https://obsidiansecurity.com/ai-agent/n8n)
- [V] Reco launched AI Agent Security on 18 March 2026 (date from search summary) "with built-in integrations for Copilot, ChatGPT Enterprise, Salesforce Agentforce, Make, and n8n"; it inventories agents and maps "access, permissions, connections, and risk posture" and surfaces "agents with risky permissions, exposed credentials, or excessive access". Zapier is not on the launch page. Owners, triggers and webhooks are not mentioned; connection method is not stated. — [Reco blog](https://reco.ai/blog/reco-launches-industry-first-ai-agent-security-to-tackle-agent-sprawl-across-saas)
- [S] Coverage of the Reco launch says detection uses recognisable "workflow signatures" of n8n, Make and Zapier, which would mean inference from SaaS-side traces rather than reading workflow definitions. **Claims VectaSec can make (as of 23 November 2026, subject to the gaps listed)**
- "No CNAPP or cloud-provider catalogue we could open reads Kafka ACLs, RabbitMQ permissions or Kong consumers; their checks are control-plane flags." Supported for AWS Security Hub, AWS Config, Azure Policy, Steampipe, Checkov, KICS. Must be scoped to catalogues that are public; Wiz, Orca, Prisma and CrowdStrike catalogues were not readable.
- "We found no single product that covers brokers, gateways, automation platforms, file transfer and MCP servers in one posture model." No counter-example found.
- "Self-managed Kafka, RabbitMQ, NATS, Kong and n8n have zero checks in Checkov, KICS, AWS Config and Security Hub." Supported by name-match counts.
- "RabbitMQ, NATS and managed file transfer have no dedicated posture product that we could find." Supported by absence in searches and catalogues; phrase as "that we could find".
- "Last-used and ownership for in-broker and gateway credentials (SCRAM users, RabbitMQ users, Redis ACL users, Kong consumers, SAS keys) is not something we found any vendor computing."
- "Pairing a configuration finding with a safe confirmation probe for brokers" as a product feature, provided it is not described as a new technique.

**Claims VectaSec must stop making**
- "Nobody does integration-layer security posture" without qualification.
- "Nobody looks inside Kafka" or "no tool audits Kafka ACLs agentlessly". KafkaGuard claims exactly this with 55 controls and SOC 2, PCI-DSS and ISO 27001 mappings.
- "Nobody assesses n8n, Zapier or Make" or "automation platforms are invisible to security tools". Obsidian, Reco, Nudge, Valence, CrowdStrike and Zenity each name at least one of these platforms.
- "First to inventory MCP servers" or any MCP-inventory novelty claim.
- "Nobody audits API gateway configuration across vendors". MuleSoft scans applied policies on Kong, AWS API Gateway, Azure APIM and Apigee, and Defender for Cloud inspects APIM subscriptions, authentication policies and unused endpoints.
- "Azure Service Bus has zero checks" stated as a market fact. It is true of Prowler, Checkov and KICS, false of Azure Policy (10 to 18) and Steampipe (6).
- "Nobody detects unused integration endpoints". Defender for Cloud flags API endpoints with no traffic for 30 days in APIM, Logic Apps and Function Apps.
- "First to safely probe brokers". Nuclei ships open-source probes for Kafka topic enumeration, RabbitMQ AMQP default login, exposed Redis and NATS enumeration.

### Gaps
- The verdict depends on catalogues that could not be opened: Wiz, Orca, Palo Alto Prisma/Cortex Cloud, CrowdStrike Falcon Cloud Security, and the per-integration check lists of Obsidian, Reco, Nudge, Valence and Falcon Shield. A buyer with access to those consoles could contradict the "control-plane only" statement for those vendors.
- KafkaGuard's claims are vendor-stated; its licence, funding, customer base and actual depth on MSK, Aiven and Redpanda ("designed to work with") were not verified. Its GitHub release repository was not opened.
- Not read at all in this pass: Wing, DoControl, Push Security, Grip (beyond one search), Tyk, 42Crunch, Wallarm, Cequence, Levo, Escape, StackHawk, Pynt docs; Tetrate, Solo.io, Buoyant, Isovalent docs; StreamNative, Aklivity; Turbot Guardrails; Crunchbase; conference exhibitor lists.
