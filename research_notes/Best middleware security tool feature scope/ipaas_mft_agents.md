## Key Question 1: Per platform, the exact posture checklist and which API provides the evidence

### Takeaway
Every platform in scope exposes a read-only management API (or an audit-log stream) sufficient to build a posture inventory of connections/credentials, flows/recipes, webhooks/public endpoints, RBAC, and version; the differentiating checks are (a) secrets embedded in flow definitions, (b) OAuth-grant scope breadth per connection, (c) webhook/public-endpoint auth, (d) credential ownership/sharing semantics (where most 2025-26 CVEs clustered), and (e) version-to-CVE with KEV tagging. Incidents 2023-2026 (MOVEit, GoAnywhere, Cleo, Salesloft Drift, Vercel/Context.ai, n8n credential-takeover CVEs, Airflow/Argo secret-leak CVEs, Milvus unauth management port) map almost one-to-one onto those five check families.

### Cited Findings

#### A. iPaaS / ESB

**MuleSoft Anypoint**
- Connected Apps (client-credentials) are created under Access Management; scopes are selected at creation, the `profile` scope is implicit, and every other permission is granted explicitly per business group and per environment — [DZone: Anypoint Platform Connected Apps](https://dzone.com/articles/anypoint-platform-connected-apps). Posture check: enumerate connected apps, their scopes x business-group x environment matrix; flag org-admin-equivalent scopes.
- June 4 2026 Access Management release note: client applications now carry a `credentialsUpdatedAt` timestamp recording last client-secret rotation (no historical backfill); client secrets have no default expiration but can be rotated — [MuleSoft Access Management release notes](https://docs.mulesoft.com/release-notes/access-management/access-management-release-notes). Posture check: secret age from `credentialsUpdatedAt`; flag never-rotated secrets.
- Audit logging: UI + "Audit Log Query API"; filter by product/type/action; search by environment/object/user; results scoped to business group; default retention 1 year (6 years for orgs created before 2023-07-10 that never changed it); requires Organization Administrator or Audit Log Viewer permission; audited products include Access Management, API Manager, DataGraph, Anypoint MQ, API Designer, Mocking Service, API Governance, Exchange, IDP, Object Store v2, RPA — [MuleSoft audit logging docs](https://docs.mulesoft.com/access-management/audit-logging). Release notes also say connected-app scope assignment ("Permission changes") is now audited — [MuleSoft Access Management release notes](https://docs.mulesoft.com/release-notes/access-management/access-management-release-notes).
- Token exchange: client credentials exchanged at the Anypoint token endpoint for a bearer token; endpoint differs by control-plane region — [DZone](https://dzone.com/articles/mule-app-deployment-using-connected-app). Posture check: which control-plane region (US/EU/GOV) each connected app targets (data-residency).

**Boomi**
- Platform API `AuditLog` object: one entry per audit event; action table enumerates type/action/modifier (account edits, API application changes, etc.); entries retained indefinitely with no purge — [Boomi Platform API: AuditLog](https://developer.boomi.com/docs/api/platformapi/AuditLog).
- `EnvironmentConnectionFieldExtensionSummary` QUERY returns extensible connection fields per environment; Environment Extensions can set nearly every extensible connection field except the OAuth 2.0 `accessToken`; the QUERY returns an OAuth token-generation URL valid for 15 minutes — [Boomi Platform API: EnvironmentConnectionFieldExtensionSummary](https://developer.boomi.com/docs/api/platformapi/EnvironmentConnectionFieldExtensionSummary). Requires API privilege plus `ATOM_MANAGEMENT` or `ATOM_MANAGEMENT_READ_ONLY` in the target environment — same source. Posture check: read-only role for the scanner = `ATOM_MANAGEMENT_READ_ONLY`; enumerate connections per environment and whether credential fields are environment-extended (good) vs hard-coded in the process (bad).
- `EnvironmentMapExtensionsSummary` covers only maps; `EnvironmentExtensions` manages connections and process properties — [Boomi Platform API: EnvironmentMapExtensionsSummary](https://developer.boomi.com/docs/api/platformapi/EnvironmentMapExtensionsSummary).
- Boomi now publishes MCP "Connect setup assistants" for ChatGPT (user path: Settings > Apps & Connectors) — [Boomi help: Connect setup assistants](https://help.boomi.com/docs/Atomsphere/Platform/Connect_setup_assistants). Posture check: iPaaS tenants are themselves becoming MCP servers; inventory them.

**Workato**
- Connections API: list/create/update/disconnect/delete; delete fails if the connection is used by active recipes or as an audit-log streaming destination — [Workato docs: Connections](https://docs.workato.com/workato-api/connections.html).
- `GET /api/activity_logs` returns the same data as the in-product Activity Audit UI, paginated and filterable; API clients get access per environment — [Workato: Activity audit log API](https://docs.workato.com/oem/oem-api/activity-reference.html); logged categories include logins, failed logins, 2FA changes, API token regeneration, API-collection endpoint activation/creation/deactivation/deletion/update, and connection changes — [Workato: Activity audit log reference](https://docs.workato.com/features/activity-audit-log-reference).
- API clients: endpoints to list/create/update/delete API clients, keys, and access profiles; Workato recommends migrating to v2 endpoints ahead of deprecation — [Workato API resources](https://docs.workato.com/workato-api/resources.html). Posture checks: API-client access-profile breadth; API-collection endpoints exposed with no auth policy; connections shared across projects.
- Gap (Workato): no documentation found on token lifetimes, rotation policy, or whether reads of the activity-log endpoint are themselves logged — [search summary].

**SnapLogic, Informatica, WSO2, TIBCO, Celigo, SAP Integration Suite** — see Gaps; no sourced API or CVE detail was retrievable in this run.

#### B. Dev / no-code automation

**n8n (self-hosted + cloud)**
- Built-in security audit: `POST /audit` on the public API (must authenticate as instance owner), CLI `n8n audit`, or n8n node (Resource=Audit, Operation=Generate). Five reports: Credentials (unused / not in active / not in recently-active workflow), Database (SQL nodes where Execute Query or Query Parameters use expressions, or params defined but unused), Filesystem (nodes touching the FS), Nodes (official risky nodes per `OFFICIAL_RISKY_NODE_TYPES` in source, community nodes, custom nodes), Instance (unprotected webhooks, missing security settings, outdated version) — [n8n docs: security audit](https://docs.n8n.io/hosting/securing/security-audit/). A community wrapper shows optional parameters `daysAbandonedWorkflow` and a category filter — [glama n8n-mcp-server generate-audit](https://glama.ai/mcp/servers/@fellipesaraiva88/n8n-mcp-server/tools/generate-audit) (unofficial).
- 2026 CVE cluster (all independently recorded in NVD/INCIBE/aggregators):
  - CVE-2026-54305 (CVSS 9.9): three Enterprise endpoints behind Dynamic Credentials lacked ownership checks; any logged-in user could list other users' credential names/types and take over or revoke their OAuth tokens; fixed 1.123.55 / 2.25.7 / 2.26.2 — [INCIBE](https://www.incibe.es/en/incibe-cert/early-warning/vulnerabilities/cve-2026-54305).
  - CVE-2026-33663: member-role user could read plaintext secrets of other users' generic HTTP credentials (community edition); fixed 1.123.27 / 2.13.3 / 2.14.1 — [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-33663).
  - CVE-2026-72763 (CVSS4 7.2, Aug 2026): credential checks skipped credentials referenced inside Execute Sub-workflow inline JSON; fixed 1.123.67 / 2.31.5 / 2.32.1 — [Lutra fieldguide](https://fieldguide.lutrasecurity.com/CVE-2026-72763/).
  - CVE-2026-103247 (5.8): duplicate node IDs bypass workflow credential tamper guard; fixed 1.123.80 — [OpenCVE](https://app.opencve.io/cve/CVE-2026-103247) (single aggregator; verify against NVD).
  - CVE-2026-25631 (Feb 2026): HTTP Request node domain-allowlist bypass when wildcard patterns used; affects <1.121.0 — [search summary; verify on NVD].
- Posture checks derived: instance version vs the above fix lines; workflow-sharing + credential-sharing graph (who can edit a workflow that references whose credential); wildcard entries in "Allowed domains"; unprotected webhook nodes; community/custom nodes installed; Dynamic Credentials feature enabled on Enterprise.

**Zapier**
- Enterprise: SAML SSO, SCIM provisioning, 2FA, custom data retention; admins can designate **Managed Apps** (only admins create/share/delete connections for those apps) and set **allowed domains for app connections** — [Zapier help: Set up admin tools for your Enterprise account](https://help.zapier.com/hc/en-us/articles/44796621276685-Set-up-admin-tools-for-your-Enterprise-account).
- Audit-log export is via **Log Streams** (Enterprise): 45+ event types covering Zaps, MCP servers, app connections, variables, account management, Tables; configured at Admin Center > Insights > Log streams; webhook delivery with optional secret for signature verification; existing streams do not auto-pick-up new event types — [Zapier blog: Log Streaming](https://zapier.com/blog/zapier-log-streaming/). Audit-log retention Team 6 months / Enterprise 1 year — [Zapier pricing](https://zapier.com/pricing.md).
- Zapier MCP: OAuth or connection-token auth; SAML SSO extends to MCP; app connections cannot be shared; account-level app/action restrictions apply to MCP automatically (cannot be set for MCP alone); all tools Zapier-owned (no third-party tool import); **no tool-level allowlist and no approval workflow documented**; any member of an MCP-enabled workspace can create servers; owners/super-admins see all servers; MCP enabled by default for all accounts incl. Enterprise; admins can disable MCP per workspace and set task quotas; History tab logs user-level tool calls, super-admins can review; MCP events appear in account audit log; data stored AWS us-east-1 multi-tenant; no API endpoints documented — [Zapier docs: MCP security](https://docs.zapier.com/mcp/security.md).
- Gap: no public REST audit-log or connections-listing API found for Zapier; evidence must come from Log Streams (push) or admin UI — [search summary].

**Make (ex-Integromat)**
- Audit logs API v2 (scope `audit-logs:read`): `GET /audit-logs/v2/organization/{organizationId}`, `.../filters`, `GET /audit-logs/v2/team/{teamId}`, `.../filters`, `GET /audit-logs/v2/{organizationId}/{uuid}`; filters `team`, `dateFrom`, `dateTo`, `event`, `author`, `pg` (sortBy triggeredAt/createdAt/eventName/targetId, cursor `last`); example events `key_created`, `connection_created` — [Make developers: Audit logs](https://developers.make.com/api-documentation/api-reference/audit-logs).
- Connections listing requires scope `connections:read`; Hooks (webhooks), Teams, Users, SSO certificates are separate API sections; API requires a paid plan — [Make Developer Hub index](https://developers.make.com/llms.txt).
- Gap: no SCIM doc found for Make — [search summary].

#### F. AI agent infrastructure

**MCP protocol & registry**
- Spec timeline: RC May 21 2026 (stateless core); EMA (Enterprise-Managed Authorization) extension stable June 18 2026, adopted by Anthropic, Microsoft, Okta; beta SDKs June 29; spec 2026-07-28 released; initialize handshake and protocol-level session removed; MRTR (Multi Round-Trip Requests); Tasks extension; MCP Apps extension (Jan 26 2026); formal deprecation policy — [MCP blog, tag MCP](https://blog.modelcontextprotocol.io/tags/mcp/). Secondary source adds: DCR deprecated in favor of Client ID Metadata Documents (CIMD) and RFC 9207 issuer claim — [wz-it](https://wz-it.com/en/knowledge/ki/mcp-model-context-protocol/) (unverified against spec text).
- Tool annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) are hints not enforcement; a tool with no annotations should be treated as destructive/non-idempotent/open-world; five SEPs propose new annotations — [MCP blog (Mar 16 2026 post, via tag page)](https://blog.modelcontextprotocol.io/tags/mcp/); [Stacklok](https://stacklok.com/blog/tool-annotations-are-becoming-the-risk-vocabulary-for-agentic-systems-that-matters-more-than-it-might-seem/).
- OWASP MCP Top 10 (v0.1): MCP01 Token Mismanagement; MCP02 Privilege Escalation via Scope Creep; MCP03 Tool Poisoning; MCP04 Supply Chain; MCP05 Command Injection; MCP06 Intent Flow Subversion (prompt injection via context); MCP07 Insufficient AuthN/AuthZ; MCP08 Lack of Audit/Telemetry; MCP09 Shadow MCP Servers; MCP10 Context Injection & Over-sharing — [Cycode guide](https://cycode.com/blog/owasp-mcp-top-10/). OWASP Top 10 for Agentic Applications 2026 (released Dec 2025) is the broader list — [OWASP GenAI](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/).
- Exposure research: Knostic (post dated July 17 2025) found 1,862 internet-exposed MCP servers via Shodan (100+ filters: `"jsonrpc":"2.0"`, `"method":"initialize"`, `text/event-stream`, paths `/mcp`, `/messages`, `/api/mcp`, `uvicorn` header); 119 manually verified, all returned `tools/list` without auth; verification was read-only (`tools/list` only, never `tools/call`) — [Knostic study](https://www.knostic.ai/blog/mapping-mcp-servers-study). Trend Micro: 492 exposed servers / 1,402 tools; later Bitsight+Trend Micro (Apr 2026) 1,467, ~3x in three months — [NHIMG summary](https://nhimg.org/articles/internet-exposed-mcp-servers-are-broadcasting-tools-without-auth/) (secondary). A Feb 2026 audit of 518 official-registry servers reportedly found 41% with zero auth — [agenticwire](https://www.agenticwire.news/article/mcp-server-exposed-check) (unverified).
- Registry supply-chain: April 2026 OX Security PoC malicious package accepted by 9 of 11 MCP registries — [pipelab](https://pipelab.org/blog/state-of-mcp-security-2026/) (secondary). Claimed Aug 2026 worm wave via official registry and May 2026 NSA MCP guidance — [glasp](https://glasp.co/articles/mcp-security-tool-poisoning-supply-chain) (**unverified; no primary source found**).
- postmark-mcp backdoor (Sept 25 2025, Snyk/Koi): npm `postmark-mcp` by user `phanpak` added hidden BCC to `phan@giftshop.club` in `sendEmail` from ~1.0.16; Koi estimated ~300 orgs; detections: block egress to giftshop[.]club, SCA for package, MCP-Scan on hosts/CI, rotate Postmark tokens — [Snyk](https://snyk.io/blog/malicious-mcp-server-on-npm-postmark-mcp-harvests-emails/). First documented in-the-wild malicious MCP server per most sources — [pipelab](https://pipelab.org/blog/state-of-mcp-security-2026/).
- Tool poisoning: Invariant Labs showed hidden instructions in tool descriptions reach the model as trusted content, demonstrated exfil in Claude Desktop/Cursor, and GitHub MCP hijack via malicious issue — [Polygraf](https://www.polygraf.ai/blogposts/mcp-tool-poisoning-mcp-vs-ai-agents/) (secondary).

**MCP posture checklist (derived, each tied to a finding above):** auth scheme on `/mcp` endpoint (none/bearer/OAuth2.1/EMA); internet reachability; `tools/list` reachable unauthenticated; tool-description hash pinning + drift (rug-pull); description scan for hidden-instruction patterns; annotation completeness and `destructiveHint`/`openWorldHint` inventory; package provenance (npm/PyPI author, version, SCA) for stdio servers; registry membership vs allowlist (shadow MCP); audience validation of tokens; tool-call audit log existence.

**A2A AgentCards**
- Card served at `/.well-known/agent-card.json` (renamed from `agent.json` in v0.3); declares skills, content types, transport, security schemes (OAuth2, OIDC, API key, mTLS); security requirements are "OR of ANDs" — [Google Cloud AgentCard reference](https://docs.cloud.google.com/gemini/data-agents/reference/rest/Shared.Types/AgentCard); [Wiz academy](https://www.wiz.io/ja-jp/academy/ai-security/a2a-protocol). A2A 1.0: optional JWS signatures over canonicalized JSON; signature proves integrity/provenance not safety; client needs issuer/key/revocation policy; three bindings (JSON-RPC, gRPC, HTTP+JSON) — [API7](https://api7.ai/blog/a2a-protocol-gateway-layer). Discovery guidance warns against static secrets in cards and recommends access control for sensitive/extended cards — [Atlan guide](https://atlan.com/know/mcp/a2a-protocol-implementation-guide/). Academic proposals on A2A data protection — [arXiv 2505.12490](https://arxiv.org/html/2505.12490v3).
- Checks: card present/public; signed?; security schemes empty; `extendedCard` behind auth; declared skills with destructive verbs; binding/TLS.

### Inferences

## Key Question 2: What "agent security posture" features buyers ask for in 2026

### Takeaway
By October 2026 the buyer checklist has converged on: (1) live agent + tool + MCP-server inventory incl. shadow discovery, (2) allowlist/registry enforcement with signed/pinned tools, (3) per-agent credential scoping and OAuth-grant inventory, (4) tool-poisoning and rug-pull detection, (5) prompt-injection surface mapping (which agents read untrusted sources), (6) immutable tool-call audit trail, (7) human-in-the-loop / "needs approval" per tool, and (8) AI-BOM. Posture vendors (Zenity, Noma) and runtime/gateway vendors (Lasso, Runlayer, Cisco DefenseClaw, Snyk Agent Scan) split along the buildtime/runtime line, and every independent review notes posture alone is a point-in-time declared-state view.

### Cited Findings
- OWASP MCP Top 10 defenses enumerate the buyer features directly: short-lived scoped tokens + secrets detection (MCP01); least-privilege scopes with automated scope expiry (MCP02); signed, pinned tools + description scanning (MCP03); signed components + AIBOM/provenance (MCP04); sandboxed execution (MCP05); context isolation / instruction quarantine (MCP06); OAuth 2.1 + MFA + per-server audience validation (MCP07); immutable audit logs + behavioral monitoring (MCP08); continuous discovery + allowlist enforcement (MCP09); scoped context windows / ephemeral memory (MCP10) — [Cycode OWASP MCP Top 10](https://cycode.com/blog/owasp-mcp-top-10/).
- Snyk Agent Scan (ex-Invariant MCP-Scan, acquired June 2025; v0.4.13 Apr 2026): detects 15+ issue types across MCP servers and agent skills incl. tool poisoning in descriptions, tool shadowing, toxic flows, malware payloads, hardcoded secrets; **Tool Pinning** tracks tool hashes over time to catch rug pulls; background mode reports to Snyk Evo dashboard (enterprise tier); caveat: executes stdio servers during interactive scans; run via `uvx snyk-agent-scan@latest` with `SNYK_TOKEN` — [Snyk Labs](https://labs.snyk.io/resources/detect-tool-poisoning-mcp-server-security/); [Rubin Lake radar](https://rubinlake.com/en/technology-radar/ai-security-and-governance/agent-scan); [dev.co](https://dev.co/ai/mcp/agent-scan).
- Cisco DefenseClaw: open-source governance layer for coding agents (Claude Code, Codex, Copilot, Cursor): scans skills, MCP servers, plugins, generated code before run; blocks risky tool calls; keeps audit trail — [DefenseClaw site](https://cisco-ai-defense.github.io/defenseclaw/) (vendor).
- Zenity: live agent inventory across SaaS/custom/endpoint; AISPM pre-deployment review of configurations, permissions, integrations, tool access for Copilot Studio, ChatGPT Enterprise, Agentforce; "Runtime Boundaries" (July 2026) checks actions pre-execution for Claude Code, Cursor, Copilot, Agentforce, Bedrock; posture derived from config/platform telemetry via agentless connectors ("declared-state view") — [Zenity AISPM](https://zenity.io/platform/ai-security-posture-management) (vendor); [Zenity Copilot Studio](https://zenity.io/use-cases/platform/microsoft-copilot-studio) (vendor); [Maxim comparison](https://www.getmaxim.ai/articles/ai-agent-security-top-5-platforms-compared-in-2026/); [NeuralTrust](https://neuraltrust.ai/blog/best-ai-spm-tools) (competitor). Zenity itself says a clean posture result doesn't settle runtime risk — [Zenity coding-agent post](https://zenity.io/blog/coding-agent-attack-surface).
- Noma Security: discovery, posture, red teaming, runtime; on-prem or cloud; credited with AI-BOM and model scanning (which Zenity reportedly lacks) — [Accuro AI](https://accuroai.co/blog/top-ai-spm-vendors-2026) (secondary). Noma found ForcedLeak — [Security Affairs](https://securityaffairs.com/182676/hacking/forcedleak-flaw-in-salesforce-agentforce-exposes-crm-data-via-prompt-injection.html).
- Lasso: runtime enforcement via proxy/API/gateway, claims sub-50 ms classification — [General Analysis](https://generalanalysis.com/guides/best-ai-security-platforms) (vendor-claimed).
- Runlayer: only placed in "gateway and MCP control plane" category alongside Lasso; no feature detail found — [Arcjet comparison](https://arcjet.com/compare/ai-agent-security-platforms).
- Cisco AI Defense vs Zenity: Cisco stronger in automated red teaming; Zenity in buildtime posture + inline enforcement in Copilot Studio — [Kosmoy](https://www.kosmoy.com/resources/blog/cisco-ai-defense-vs-zenity/) (opinion, commercial angle).
- None of Zenity/Noma/Lasso/Runlayer publish list pricing — [TechPilot](https://techpilot.ai/ai-agent-security-tools/).
- Human-in-the-loop as product control: Claude Team/Enterprise per-tool Always allow / Needs approval / Blocked — [Sunpeak](https://sunpeak.ai/blogs/what-are-claude-connectors/) (secondary). Zapier MCP documents no approval workflow — [Zapier MCP security](https://docs.zapier.com/mcp/security.md).
- Tool annotations as "risk vocabulary" for allowlists; five SEPs pending — [Stacklok](https://stacklok.com/blog/tool-annotations-are-becoming-the-risk-vocabulary-for-agentic-systems-that-matters-more-than-it-might-seem/).
- Snyk's own IR recipe for postmark-mcp = SCA + AIBOM + MCP-Scan on hosts and CI + egress block + token rotation, i.e., the AI-BOM/inventory/egress triad — [Snyk](https://snyk.io/blog/malicious-mcp-server-on-npm-postmark-mcp-harvests-emails/).
- CSA post-Vercel controls = formal inventory of AI tools holding OAuth grants with scopes, authorizing identity, IT-vs-individual provenance; automated revocation — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-saas-supply-chain-vercel-contextai-2026/).

### Inferences
- Posture vendors are differentiated by *which platforms* they have agentless connectors into (Zenity: Copilot Studio/Agent 365/Agentforce/ChatGPT Enterprise; Noma: AI-BOM/model scanning; Snyk: developer hosts and CI). None of the found sources describe any vendor connecting to n8n/Zapier/Make/Workato/MuleSoft as agent-tool hosts — those platforms are now MCP servers and tool providers themselves (Zapier MCP, Boomi MCP assistants).
- "Rug-pull detection" has a concrete, commodity implementation (hash-pin `tools/list` responses and alert on drift) — Snyk ships it; a posture tool must match it as table stakes.
- AI-BOM in buyer language = (agents, models, tools/MCP servers, their package provenance, their OAuth grants, their data sources); CSA's inventory and OWASP MCP04 both describe it.

### Gaps
- No independent head-to-head of Zenity/Noma/Lasso/Runlayer; Runlayer effectively undocumented in retrieved sources.
- Wiz AI-SPM feature detail not retrieved (search budget).
- Microsoft Agent 365 / "security admin API" docs not retrieved.
- Whether Claude Enterprise audit logs include tool-call events is only asserted by a competitor; needs the official doc.

## Key Question 3: Where is the blind spot nobody covers

### Takeaway
Four blind spots are evidence-backed: (1) SMB-scale automation (Zapier/n8n/Make) holding production credentials — n8n's 2026 credential-takeover CVE cluster and Zapier's default-on MCP with no tool allowlist, yet SSPM coverage lists never mention these platforms; (2) MFT appliances — repeatedly mass-exploited (2023, 2024, 2025) but their admin-console exposure and API-token scoping are not an SSPM/AI-SPM category; (3) enterprise AI connectors (Claude/ChatGPT/Copilot) — governance is split between vendor admin UIs with no documented read APIs, and tool-call audit coverage is disputed; (4) vector DBs — default-no-auth, management ports open (Milvus 9091), thousands exposed (Chroma 1,170), and no competitor found covers them as posture targets.

### Cited Findings
- SSPM coverage claims never list automation platforms: AppOmni "150+ apps with deep models", Obsidian "200+ integrations", Valence "175+" / "100+"; Reco's Oct 2025 table says AppOmni <40 and Obsidian >40 — counts conflict and none name Zapier/n8n/Make/Workato — [guptadeepak SSPM list](https://guptadeepak.com/tools/top-10-sspm-tools-2026/); [dope.security](https://dope.security/post/obsidian-security-alternatives); [Reco comparison](https://www.reco.ai/compare/obsidian-security-vs-appomni). Valence is described as strongest on SaaS-to-SaaS/OAuth integration risk — [DoControl](https://www.docontrol.io/blog/top-10-appomni-competitors-and-alternatives). Nudge: no coverage info found.
- Zapier MCP enabled by default for all accounts incl. Enterprise; no tool-level allowlist or approval; any workspace member can create servers — [Zapier MCP security](https://docs.zapier.com/mcp/security.md). Third-party access-review tooling exists because Zapier lacks native review workflow — [Torii](https://www.toriihq.com/articles/comparing-zapier-access-review-tools) (vendor).
- n8n: four 2026 CVEs let one tenant user read/takeover another's credentials or redirect secrets (CVE-2026-54305, -33663, -72763, -103247) — [INCIBE](https://www.incibe.es/en/incibe-cert/early-warning/vulnerabilities/cve-2026-54305); [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-33663); [Lutra](https://fieldguide.lutrasecurity.com/CVE-2026-72763/); [OpenCVE](https://app.opencve.io/cve/CVE-2026-103247).

- Vector DBs: Milvus default-exposed 9091 with weak token (CVE-2026-26190, 9.8) — [Wiz](https://www.wiz.io/vulnerability-database/cve/cve-2026-26190); 1,170 exposed Chroma instances — [BeyondScale](https://beyondscale.tech/blog/vector-database-security-enterprise-ai); Weaviate RBAC privesc — [cve-dev](https://cve-dev.imfht.com/product/weaviate?lang=en). No competitor page retrieved lists vector DBs as a posture target.

## Key Question 4: Which checks are unique vs commodity

### Takeaway
Commodity (every competitor or open-source tool does it): version-to-CVE/KEV, exposed-port/unauth-endpoint detection, tool-description poisoning scans, tool-hash rug-pull pinning, DLP connector grouping, OAuth-app listing in SaaS admin consoles. Unique (not found in any retrieved competitor): cross-platform credential→grant→downstream-scope graph across iPaaS + automation + agent hosts; secrets-in-flow-definition detection across recipe/flow JSON (n8n, Boomi process, Workato recipe, Airflow `extra`, Argo templates); per-tenant credential-sharing/ownership graph modeled against the 2026 n8n CVE patterns; MFT admin-tier exposure + API-token scope + session-expiry checks; vector-DB management-port + RBAC + DSPM join; A2A AgentCard signature/scheme checks; MCP-server-from-iPaaS inventory (Zapier MCP, Boomi MCP).

### Cited Findings
- Commodity — tool poisoning / rug pull / shadowing / hardcoded secrets in MCP: shipped by Snyk Agent Scan (open-source lineage) — [Snyk Labs](https://labs.snyk.io/resources/detect-tool-poisoning-mcp-server-security/); Cisco DefenseClaw (open source) — [DefenseClaw](https://cisco-ai-defense.github.io/defenseclaw/); checklists widely published — [Cohorte](https://cohorte.co/blog/mcp-security-tool-poisoning-checklist).
- Commodity — exposed MCP discovery via Shodan fingerprints (`/mcp`, `text/event-stream`, `"method":"initialize"`) — [Knostic](https://www.knostic.ai/blog/mapping-mcp-servers-study); [Doppler guide](https://www.doppler.com/guides/mcp-server-security-risks-attack-scenarios/exposed-remote-mcp-servers).
- Commodity — agent inventory + config/permission review for Copilot Studio/ChatGPT Enterprise/Agentforce: Zenity, Noma — [Zenity AISPM](https://zenity.io/platform/ai-security-posture-management); [Accuro](https://accuroai.co/blog/top-ai-spm-vendors-2026).
- Commodity — Power Platform DLP Business/Non-business/Blocked grouping is a native Microsoft control — [Microsoft Learn](https://learn.microsoft.com/ro-ro/microsoft-copilot-studio/admin-data-loss-prevention).
- Commodity — OAuth-grant inventory in SaaS consoles (Google Workspace Admin third-party app audit) — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-saas-supply-chain-vercel-contextai-2026/); Valence/Obsidian/AppOmni do SaaS-to-SaaS OAuth risk — [DoControl](https://www.docontrol.io/blog/top-10-appomni-competitors-and-alternatives).
- Commodity — n8n's own `/audit` already flags unused credentials, risky nodes, unprotected webhooks, outdated version — [n8n docs](https://docs.n8n.io/hosting/securing/security-audit/). A posture tool must go beyond this (sharing graph, allowlist wildcards, sub-workflow credential refs) to add value.
- Unique-candidate evidence: no competitor source mentions Make `audit-logs:read`/`connections:read` — [Make docs](https://developers.make.com/api-documentation/api-reference/audit-logs); Boomi `EnvironmentConnectionFieldExtensionSummary` / `ATOM_MANAGEMENT_READ_ONLY` — [Boomi](https://developer.boomi.com/docs/api/platformapi/EnvironmentConnectionFieldExtensionSummary); MuleSoft `credentialsUpdatedAt` secret-age — [MuleSoft RN](https://docs.mulesoft.com/release-notes/access-management/access-management-release-notes); Workato `GET /api/activity_logs` + API-client access profiles — [Workato](https://docs.workato.com/workato-api/resources.html); MOVEit API-token scope bypass class (CVE-2026-10698) and session expiry (CVE-2026-15967) — [stack.watch](https://stack.watch/product/progess/moveit-transfer/); Milvus 9091 — [Wiz](https://www.wiz.io/vulnerability-database/cve/cve-2026-26190); A2A card JWS verification policy — [API7](https://api7.ai/blog/a2a-protocol-gateway-layer).
- Unique-candidate: Agentforce Trusted-URL domain-expiry check (the ForcedLeak exfil domain was expired and purchasable) — [Security Affairs](https://securityaffairs.com/182676/hacking/forcedleak-flaw-in-salesforce-agentforce-exposes-crm-data-via-prompt-injection.html); no vendor page retrieved advertises a "allowlisted domain registration status" check.

### Inferences
- The defensible moat is the join, not any single check: (connection in Workato/Boomi/n8n/Zapier) ↔ (OAuth grant + scopes in the downstream SaaS) ↔ (MCP tool exposing that connection to an agent) ↔ (vector DB / data classification). Each leg is commodity in isolation; nobody retrieved does the full path.
- "Allowlisted domain is expired/unregistered" (Agentforce, n8n allowed-domains wildcards, Workato/Make webhook targets) is a cheap, novel, high-signal check derivable from the ForcedLeak and n8n CVE-2026-25631 patterns.
- MFT checks are unique only because competitors ignore the category; the checks themselves are conventional (exposure, version, token scope, session config).

### Gaps
- Could not confirm whether Wiz AI-SPM, Noma, or Runlayer already cover vector DBs, A2A cards, or iPaaS-as-MCP-server inventory; absence in retrieved pages is weak evidence.
- Could not verify claims of a May 2026 NSA MCP guidance document or an Aug 2026 registry worm wave; both appear only in secondary blogs.
