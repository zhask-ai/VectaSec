# VectaSec — Coverage Matrix

**As of 2026-07-23.** This is the public, falsifiable statement of what VectaSec can and cannot
see. Every row was generated by reading the registry (`cd services/engine && uv run vectasec rules`
— on this date: **129 rules across 9 packs, 7 connectors**) and the named `connect/*.py` /
`detect/*.py` files. If a system is not in this file, VectaSec does not cover it. If a caveat is
missing, that is a bug in this file — the code is the authority, and this document's only value is
being checkable against it.

Conventions used below:

- **Reads** — the actual APIs the connector calls. Every connector is read-only by contract
  (List/Get/Describe-class calls only; nothing anywhere writes to a customer system).
- **NHI** — whether the connector's output feeds the normalized non-human-identity derivation
  (`identity.py` / `@identity_extractor`), yielding `identity` / `credential` / `grant` resources
  and their edges. Credential *values* are never read or stored by any connector — metadata only.
- **Edges** — whether the connector emits graph edges of its own (the NHI layer adds
  `credential_of` / `granted_to` / `grants_access` edges on top for every connector with NHI = yes).
- **Not covered** — the honest gaps, from the connector/detector docstrings. "Not covered" means
  *no code*; it never means "probably fine".

The two cross-cutting packs run on every connector's normalized output and are counted once, not
per system: **NHI (4 rules)** on `identity`/`credential`/`grant` kinds, and **DATA (2 rules)** on
data-carrying kinds (`classify.py` sensitivity tagging; `DATA.EXPOSURE.SENSITIVE_PLAINTEXT` is the
toxic-combination rule). 21+18+20+16+24+18+6 per-system + 4 + 2 = 129.

## Covered systems

### Kafka — `connect/kafka.py`, `detect/kafka.py` (20 rules: 2 critical, 10 high, 5 medium, 3 low)

| | |
|---|---|
| **Reads** | Kafka Admin API (confluent-kafka `AdminClient`): `list_topics` (cluster metadata), `describe_configs` (broker + topic configs), `describe_acls` (ACL bindings). |
| **Kinds** | `broker`, `topic` |
| **Edges** | Yes — `broker --hosts--> topic`, linked to the brokers that lead the topic's partitions. |
| **NHI** | Yes — ACL principals become `identity` + `grant` resources (Kafka exposes no principal secrets; recorded honestly as no credential material readable). |
| **Rules cover** | Listener/security-protocol posture (PLAINTEXT, SASL_PLAINTEXT, SASL/PLAIN and SCRAM without TLS, unsecured OAUTHBEARER JWT), authorizer presence and `allow.everyone.if.no.acl.found`, wildcard/anonymous/prefixed ACLs, TLS client auth + hostname verification, legacy ZooKeeper mode, durability (`min.insync.replicas`, unclean leader election), retention, topic auto-create. |
| **Not covered** | Consumer groups, quotas, delegation tokens, Kafka Connect / Schema Registry, client-side configs, broker OS/JVM posture. PASSWORD-typed broker configs are redacted by the broker itself — rules that need them say *not settled by this scan* rather than guessing (the assessability state exists for exactly this). Managed MSK properties (public access, IAM auth, encryption blocks) are covered by the **AWS** connector, not this one. |

### Kong — `connect/kong.py`, `detect/kong.py` (16 rules: 7 high, 4 medium, 4 low, 1 info)

| | |
|---|---|
| **Reads** | Kong Admin API: `/` (node + config), services, routes, plugins, consumers with per-type credential *counts*; Enterprise probes for `/rbac/users`, `/workspaces`. |
| **Kinds** | `broker` (the Kong node — the rulepack's node-level kind), `service`, `route`, `plugin`, `consumer` |
| **Edges** | Yes — `route --routes_to--> service`, plugin `--scoped_to-->` its service/route/consumer/node. |
| **NHI** | Yes — consumers become `identity` resources with credential-count metadata (key values are never read). |
| **Rules cover** | Admin API exposure (wildcard bind, plaintext, unauthenticated), routes with no auth plugin in effect (including anonymous-fallback), CORS wildcard-with-credentials, disabled security plugins, rate-limiting absence and fail-open, request-size limits, plaintext route protocols, Host-forwarding, Enterprise RBAC off, version floors for CVE-2021-27306 and CVE-2026-6338. |
| **Not covered** | DB-less/declarative config files (only a live Admin API is read), Kong Ingress Controller CRDs (see the K8s connector for Gateway API), upstream/target health, mTLS between Kong and upstreams, developer-portal posture. The two CVE rules are version-floor checks, not a CVE scanner. |

### RabbitMQ — `connect/rabbitmq.py`, `detect/rabbitmq.py` (18 rules: 1 critical, 4 high, 7 medium, 5 low, 1 info)

| | |
|---|---|
| **Reads** | Management HTTP API: `/api/overview`, `/api/nodes`, `/api/users`, `/api/permissions`, `/api/vhosts`, `/api/whoami`, plus a probe of the obsolete `/api/auth` disclosure endpoint. |
| **Kinds** | `node`, `vhost`, `user`, `permission` |
| **Edges** | Yes — `cluster --member--> node`, `permission --grants--> user`, `permission --scopes--> vhost`. |
| **NHI** | Yes — users + permissions become `identity`/`credential`/`grant` (password *hashes* are inspected for algorithm strength, then dropped — never stored). |
| **Rules cover** | guest/guest remote login and default-guest presence, management UI over plaintext, AMQP plaintext listeners, ANONYMOUS SASL, x509 auth without peer verification, wildcard permissions, weak (MD5) password hashing, admin-tag sprawl, default-vhost sharing, EOL series and unpatched-CVE version floors, Erlang distribution port exposure, CVE-2026-57219 OAuth secret disclosure. |
| **Not covered** | Brokers without the management plugin (the AMQP protocol itself is never spoken), queue/exchange-level posture (TTLs, DLX wiring), federation/shovel links, LDAP/OAuth backend configuration beyond what `/api/overview` reports. Version rules are version checks, not a CVE scanner. `RABBITMQ.SCAN.NOT_ASSESSABLE` fires — as a state, not prose — when the scanning credential cannot read part of the surface. |

### Redis — `connect/redis.py`, `detect/redis.py` (6 rules: 1 critical, 3 high, 2 medium)

| | |
|---|---|
| **Reads** | `INFO`, `CONFIG GET`, `ACL LIST` / `ACL WHOAMI` (redis-py). The `requirepass` value is dropped at the connector — never stored. |
| **Kinds** | `redis_server`, `redis_user` |
| **Edges** | No — the one connector that emits none (a single server with its users has no topology to draw). |
| **NHI** | Yes — ACL users become `identity`/`credential` (nopass / password-set metadata only). |
| **Rules cover** | Unauthenticated access, protected-mode off, bind-all, no TLS listener, ACL users with `nopass`, RediShell (CVE-2025-49844) version floor. |
| **Not covered** | Cluster and Sentinel topologies (a node is scanned as a standalone), keyspace contents (no data is ever read), Lua/module posture, managed-Redis control planes (ElastiCache/MemoryDB are not reached by the AWS connector either — a real gap). The RCE rule is a version check, not a CVE scanner. |

### MCP — `connect/mcp.py`, `detect/mcp.py` (24 rules: 9 high, 6 medium, 8 low, 1 info)

| | |
|---|---|
| **Reads** | Streamable HTTP MCP, **both protocol generations**: the 2026-07-28 stateless `server/discover` RPC first, falling back to the `initialize` handshake for servers ≤ 2025-11-25 (which generation the server speaks is recorded on the resource). `tools/list`, unauthenticated OAuth-discovery GETs (Protected Resource Metadata, AS metadata). Optional `active_probes`: invalid protocol version, forged Origin, session-entropy sampling, TLS downgrade handshake. `tools/call` is **never** issued. |
| **Kinds** | `mcp_server`, `mcp_tool` |
| **Edges** | Yes — `mcp_server --exposes--> mcp_tool`. |
| **NHI** | Yes — OAuth client/scope surface becomes `identity`/`grant` metadata. |
| **Rules cover** | Tool poisoning (hidden instructions, invisible/control characters, schema poisoning, unusual Unicode), server-instruction injection, auth-spec conformance (PRM, PKCE S256, AS metadata, RFC 9207 `iss`, overbroad scopes), transport (plaintext/invalid-cert/TLS floor, deprecated HTTP+SSE, Origin and protocol-version validation), session hygiene (predictable/colliding ids, session-as-credential), and 2026-07-28 lifecycle posture (legacy spec revision, deprecated features advertised, protocol-session dependency, Trace Context support). |
| **Not covered** | stdio-transport servers (HTTP only), fleet/shadow-MCP discovery (one server per connection — you scan what you name), registry/allowlist diffing and rug-pull detection, tool-invocation behaviour (`tools/call` is out of bounds by design), agent-side (client) posture. The injection rules are deterministic pattern checks — they catch known patterns, not novel prose attacks. |

### AWS — `connect/aws.py`, `detect/aws.py` (21 rules: 3 critical, 7 high, 6 medium, 4 low, 1 info)

| | |
|---|---|
| **Reads** | One connection fans out per configured region over five services, strictly List*/Get*/Describe*: **SQS** (queues + attributes incl. policy/encryption/DLQ, queue tags), **SNS** (topics, attributes, subscriptions, tags), **EventBridge** (buses + policies, rules, targets), **MSK** (clusters: client auth, encryption in transit, public access, monitoring, tags), **API Gateway** v1 REST + v2 HTTP/WebSocket (routes, authorizers, stages, tags). Plus one **global IAM pass** — `iam:ListUsers/ListRoles/GetRole/ListAccessKeys/GetAccessKeyLastUsed/ListUserTags/ListRoleTags` and IAM Access Advisor (`Generate`/`GetServiceLastAccessedDetails`, polled with a bounded wait; capped at 500 principals, truncation recorded) — and a per-region `cloudtrail:LookupEvents` pass (90-day window, 5 events per principal, ≤50 principals per region). Auth: cross-account read-only `AssumeRole` (with ExternalId) — the agentless path — or a named profile or key pair; `sts get-caller-identity` proves the credential before fan-out. Role template: `deploy/aws/vectasec-readonly-role.yaml`. |
| **Kinds** | `aws_account`, `aws_sqs_queue`, `aws_sns_topic`, `aws_sns_subscription`, `aws_event_bus`, `aws_event_rule`, `aws_event_target`, `aws_msk_cluster`, `aws_api`, `aws_api_stage`, `aws_iam_user`, `aws_iam_role` |
| **Edges** | Yes — account `--exposes-->` resources, rule `--targets-->` / `--delivers_to-->` targets, API `--routes_to-->` integrations, policy-derived `granted_to`/`grants_access`. |
| **NHI** | Yes — principals named in resource policies become `identity`/`grant` resources, and every IAM user/role the global pass enumerates becomes an `identity` (merged with the policy-named one when it is the same ARN) with one `access_key` **credential per access key** (masked key id, `created_at`, `status`, `last_used_at` — `None` = exists but never used) and one `role_session` credential per role (`created_at`, `last_used_at` from `RoleLastUsed`). **Last used** = newest of Access Advisor `LastAuthenticated`, key `LastUsedDate`, `RoleLastUsed`, CloudTrail newest event; recorded as `raw.last_used_at`/`last_used_source` and mirrored to `labels.last_used_at` (`"never"` when readable-and-empty; absent when not readable). **Owner** = first present of tag keys owner/team/service/contact/email/vectasec:owner/created-by/CreatedBy (case-insensitive) → `raw.owner={label,source}` + `labels.owner_label` on identities/credentials and `raw.owner` on queues, topics, clusters and APIs where tags were read. With these, `CREDENTIAL.LIFECYCLE.NEVER_USED` (never-used and >90-day-dormant keys/roles), `ROTATION_STALE` (keys created >365 days ago) and `STATIC_NO_ROTATION` (every access key) fire **assessed** for AWS; a principal whose signal was denied stays not-assessable. |
| **Rules cover** | Public resource policies (queue/topic/bus open to any principal), wildcard-action policies, MSK plaintext/unauthenticated/public access and inter-broker plaintext, API routes with no authorizer or API-key-only auth, encryption at rest off, cross-account EventBridge targets, hygiene (stage logging, WAF, DLQ, monitoring level). Every AccessDenied — per attribute call or per whole service — becomes a **not-assessable** coverage-gap finding, never a pass. |
| **Not covered** | Step Functions, Lambda, Kinesis, ElastiCache/MemoryDB, AWS Organizations enumeration (regions and the account are explicit config — nothing walks an org), IAM policies/permission boundaries attached to users and roles (grants still come only from resource policies), service-linked roles (skipped: AWS-managed), console passwords/MFA, CloudTrail data events (only management events via `LookupEvents`; for roles the Username lookup is best-effort because CloudTrail records the session name — `RoleLastUsed` is the authoritative role signal, and it only looks back 400 days). |

### Kubernetes — `connect/k8s.py`, `detect/k8s.py` (18 rules: 2 critical, 6 high, 9 medium, 1 low)

| | |
|---|---|
| **Reads** | Kubernetes API, LIST/GET only: core (namespaces, Services, ServiceAccounts, SA-token Secrets, Ingresses), RBAC (Cluster/RoleBindings, Cluster/Roles), and the CRD surfaces that answer: **Istio** (PeerAuthentication, AuthorizationPolicy, DestinationRule, Gateway, VirtualService), **Linkerd** (Server, ServerAuthorization), **Gateway API** (GatewayClass, Gateway, HTTPRoute — the shared surface of Envoy Gateway, Traefik v3, Istio's gateway). A 404 on a CRD group means "not installed" (fewer kinds); a 403 is recorded and becomes a not-assessable finding, never silence. Token Secret `data` never leaves the metadata snapshot. |
| **Kinds** | `k8s_cluster`, `k8s_namespace`, `k8s_service`, `k8s_service_account`, `k8s_sa_token_secret`, `k8s_ingress`, `k8s_gateway_class`, `k8s_gateway`, `k8s_http_route`, RBAC binding/role kinds, `mesh_peer_authentication`, `mesh_authorization_policy`, `mesh_destination_rule`, `mesh_gateway`, `mesh_virtual_service`, `mesh_server_authorization` |
| **Edges** | Yes — bindings `--binds-->`/`--authorizes-->` subjects, tokens `--token_of-->` service accounts, gateways/routes `--serves-->`/`--applies_to-->` their targets. |
| **NHI** | Yes — ServiceAccounts, their token secrets, and RBAC grants become `identity`/`credential`/`grant`. |
| **Rules cover** | Mesh mTLS not STRICT (per-policy and mesh-wide default absence), allow-all AuthorizationPolicies, DestinationRule TLS disable, plaintext mesh/API gateways and listeners, Ingress without TLS, LoadBalancer/NodePort exposure, RBAC (anonymous/all-authenticated bound, cluster-admin at cluster scope, wildcard verbs×resources), default-SA with grants + automount, legacy long-lived token secrets, collection-forbidden coverage gaps. |
| **Not covered** | Cilium and Consul mesh CRDs, NetworkPolicies, Pod/workload security context posture, admission-controller configuration, runtime behaviour (no sensor), managed-control-plane specifics (EKS/GKE/AKS APIs are not called — only what the cluster API itself serves). Traefik/NGINX are seen only insofar as they implement Gateway API/Ingress; their native config files are not read. |

| Pack | Rules | Runs on | Notes |

## Not yet supported

No code exists for any of these. Ordering follows the connector roadmap in
[vectasec-v4-blueprint.md](vectasec-v4-blueprint.md) Part 3 — force-multipliers first, then
category completion, then the long tail.

**Wave 1 remainder (force multipliers):**

- **Azure** (ARM: Service Bus, Event Hubs, APIM, Logic Apps)
- **GCP** (Pub/Sub, Apigee)

**Wave 2 (category completion):**

- n8n (public API)
- MuleSoft Anypoint
- NATS
- IBM MQ (REST admin)
- Confluent Cloud
- SaaS OAuth-grant posture (Salesforce connected apps — the Drift/Gainsight pattern)

**Wave 3 (long tail):**

- Boomi, Workato
- ActiveMQ / Artemis, Pulsar, Solace
- Tyk / Traefik / NGINX native config posture (Gateway API/Ingress surfaces are covered by the K8s connector; their own config files are not)
- Managed Istio control planes (Istio CRDs are covered via any cluster the K8s connector can reach; vendor-managed control-plane APIs are not)
- Temporal, Airflow
- Debezium / Kafka Connect
- Apollo GraphOS, LiteLLM / AI-gateway posture

Also not supported anywhere: runtime/east-west traffic observation (no sensor), SBOM/CVE scanning
(the version rules above are version-floor checks), and integration-as-code static analysis
(DataWeave, gateway policy files, workflow JSON).
